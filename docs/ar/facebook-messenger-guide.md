# دليل قناة Facebook Pages / Messenger

هذا الدليل لصاحب الوكالة الذي ينصّب OpenReply على VPS ويشغّله لعدة براندات، ولفرق هذه البراندات.

أسماء الأزرار والتبويبات والشاشات مكتوبة بين «» كما تظهر في الواجهة العربية. أسماء شاشات Meta وTelegram مكتوبة بالحروف اللاتينية كما تظهر هناك، وقد تغيّرها Meta من وقت لآخر.

## 1. ما تفعله القناة وما تحتاجه

### ما تفعله

- **التعليقات:** يعلّق شخص على منشور بكلمة مثل «سعر». يصله رد خاص على Messenger فيه رسالة وزر لصفحة الهبوط، مع رد علني اختياري تحت التعليق.
- **البوت:** يجيب على رسائل Messenger بالذكاء الاصطناعي (Gemini)، من قاعدة معرفة وكتالوج خاصين بكل براند. يفهم الدارجة والفرنسية والعربية.
- **لا اختراع:** حارس برمجي يمنع كل سعر أو رقم أو رابط أو وعد (تخفيض، توصيل مجاني، هدية، ندرة، ضمان) غير مكتوب عند البراند. إن لم يجد البوت الجواب يرسل «نرجعولك» ويحوّل المحادثة لإنسان.
- **الرسائل الصوتية:** تُفرَّغ إلى نص، والبوت يجيب عليها كأنها مكتوبة.
- **الصور:** يقرأ البوت الكود أو رقم اللون المكتوب على صورة الزبون، فيعرف المنتج. ويرسل صور الألوان والمقارنات مع زر «نحب هذا».
- **الطلبيات:** يجمع البوت معلومات الطلبية (الولاية، اللون، الكمية، الاسم، الهاتف). حين تكتمل، يصل الفريقَ تنبيه «طلبية جاهزة للتأكيد».
- **التحويل لإنسان:** تنبيه فوري على Telegram أو بالبريد، حسب سبب التحويل.
- **صندوق رسائل:** يرى فيه الفريق كل المحادثات، ويتولّاها، ويرجعها للبوت.
- **الوكالة:** كل براند مساحة مستقلة بصفحاته ومنتجاته ومحادثاته وتنبيهاته. فريق البراند لا يرى إلا براندَه.
- **قاعدة: لا شيء يستخرجه الذكاء الاصطناعي يُستعمل قبل أن يعتمده إنسان.**

### ما تحتاجه

| الحاجة | ملاحظة |
| --- | --- |
| VPS | Ubuntu أو Debian مع وصول SSH. 2 GB RAM على الأقل، و4 GB أريح لبناء الصور |
| دومين فرعي | مثل `bot.example.com`، تتحكم في سجلات DNS الخاصة به |
| تطبيق Meta | على developers.facebook.com، وحسابك مسؤول عن الصفحات |
| مفتاح Gemini | من Google AI Studio |
| بريد لتسجيل الدخول | حساب Resend، أو سيرفر SMTP خاص بك |
| بوت Telegram | اختياري: للتنبيهات وللمقابلة الصوتية |

## 2. تجهيز السيرفر والتنصيب

### 2.1 الدومين

1. ادخل لوحة التحكم في الدومين.
2. أضف سجلاً من نوع **A**: الاسم `bot` (أو ما تختار)، والقيمة عنوان IP الخاص بالـ VPS.
3. انتظر حتى ينتشر السجل. تحقق منه من جهازك:

   ```bash
   nslookup bot.example.com
   ```

### 2.2 Docker

1. ادخل السيرفر بـ SSH.
2. ثبّت Docker مع إضافة Compose:

   ```bash
   curl -fsSL https://get.docker.com | sh
   ```

3. تأكد من التثبيت:

   ```bash
   docker compose version
   ```

4. افتح المنافذ 22 و80 و443 إن كان الجدار الناري مفعّلاً:

   ```bash
   ufw allow OpenSSH
   ```

   ```bash
   ufw allow 80/tcp
   ```

   ```bash
   ufw allow 443/tcp
   ```

   ```bash
   ufw allow 443/udp
   ```

   إن كان لمزوّد الـ VPS جدار ناري في لوحته (مثل Hostinger)، افتح فيه 80 و443 أيضاً.

### 2.3 تحميل المشروع

1. انسخ المستودع إلى `/opt/openreply` (ضع رابط مستودعك):

   ```bash
   git clone https://github.com/<حسابك>/openreply.git /opt/openreply
   ```

2. ادخل مجلد ملفات الـ VPS. **كل أوامر Docker في هذا الدليل تُشغَّل من هذا المجلد:**

   ```bash
   cd /opt/openreply/deploy/vps
   ```

### 2.4 ملف `.env`

1. انسخ النموذج:

   ```bash
   cp .env.example .env
   ```

2. احمِ الملف:

   ```bash
   chmod 600 .env
   ```

3. ولّد الأسرار، كل أمر لقيمة:

   ```bash
   openssl rand -hex 24
   ```

   لـ `POSTGRES_PASSWORD`.

   ```bash
   openssl rand -base64 32
   ```

   مرة لـ `NEXTAUTH_SECRET`، ومرة أخرى لـ `CRON_SECRET`.

   ```bash
   openssl rand -hex 32
   ```

   لـ `ENCRYPTION_KEY` (64 حرفاً).

   ```bash
   openssl rand -hex 16
   ```

   لـ `FACEBOOK_WEBHOOK_VERIFY_TOKEN`.

4. افتح الملف واملأه:

   ```bash
   nano .env
   ```

5. القيم الإجبارية:

   | المتغير | القيمة |
   | --- | --- |
   | `DOMAIN` | الدومين الفرعي، مثل `bot.example.com` |
   | `ACME_EMAIL` | بريدك، تصله تنبيهات شهادة Let's Encrypt |
   | `POSTGRES_PASSWORD` | من الأمر أعلاه |
   | `NEXTAUTH_SECRET` و`CRON_SECRET` و`ENCRYPTION_KEY` | من الأوامر أعلاه |
   | `RESEND_API_KEY` أو `EMAIL_SERVER` | لإرسال روابط الدخول |
   | `EMAIL_FROM` | مرسل روابط الدخول، من دومين موثَّق عند Resend |
   | `FACEBOOK_APP_ID` و`FACEBOOK_APP_SECRET` | من تطبيق Meta (القسم 3) |
   | `FACEBOOK_WEBHOOK_VERIFY_TOKEN` | من الأمر أعلاه |
   | `GOOGLE_API_KEY` | مفتاح Gemini |

6. قيم ننصح بها:
   - `ALLOWED_EMAILS=بريدك`: يغلق التسجيل على غيرك. فرق البراندات المدعوّة تدخل رغم ذلك.
   - `AGENCY_OWNER_EMAILS=بريدك`: وحدك تنشئ البراندات.
   - `DEFAULT_LOCALE=ar`: الواجهة بالعربية لكل زائر جديد. هي مضبوطة أصلاً في النموذج.

7. قواعد الملف:
   - لا تكتب `$` ولا علامات اقتباس داخل القيم.
   - لا تضف `DATABASE_URL` ولا `REDIS_URL` ولا `NEXTAUTH_URL`: ملف Compose يضبطها.
   - **احفظ نسخة من `ENCRYPTION_KEY` خارج السيرفر.** بدونه لا يمكن قراءة توكنات الصفحات وTelegram المحفوظة.

**مفتاح Gemini:** ادخل aistudio.google.com بحساب Google، ثم Get API key، ثم Create API key. الصقه في `GOOGLE_API_KEY`.

### 2.5 التشغيل

1. تحقق من الملف والقيم الإجبارية:

   ```bash
   docker compose config -q
   ```

   إن لم يطبع شيئاً فالملف سليم.

2. ابنِ وشغّل:

   ```bash
   docker compose up -d --build
   ```

   البناء الأول يأخذ عدة دقائق. التطبيق يطبّق الـ migrations قبل أن يبدأ، والعمّال وCaddy ينتظرونه.

3. تحقق من الحاويات:

   ```bash
   docker compose ps
   ```

   الخدمات: `app` و`worker` و`facebook-worker` و`cron` و`postgres` و`redis` و`caddy`. كلها يجب أن تكون `running`، و`app` بحالة `healthy`.

4. Caddy يجلب شهادة HTTPS وحده خلال دقيقة أو اثنتين.

### 2.6 أول تسجيل دخول

1. افتح `https://bot.example.com/login`.
2. اكتب بريدك في «البريد الإلكتروني للعمل».
3. اضغط «أرسل لي رابط دخول بالبريد».
4. افتح الرابط من بريدك **على نفس الجهاز**.
5. تدخل «لوحة التحكم». أول حساب يحصل تلقائياً على مساحة عمل يكون مالكها.
6. إن لم تظهر الواجهة بالعربية: «الإعدادات» ← «لغة الواجهة» ← العربية.

## 3. تطبيق Meta

### 3.1 إنشاء التطبيق

1. ادخل developers.facebook.com بحسابك الذي يدير الصفحات.
2. My Apps ← Create App.
3. اختر حالة الاستعمال Other، ثم نوع التطبيق Business. (إن عرضت Meta حالة استعمال خاصة بـ Messenger فهي تصلح أيضاً.)
4. اكتب اسم التطبيق وبريد التواصل، واربطه بحساب Business إن وُجد.
5. من App settings ← Basic:
   - انسخ App ID إلى `FACEBOOK_APP_ID`.
   - اضغط Show بجانب App secret، وانسخه إلى `FACEBOOK_APP_SECRET`.
   - Privacy Policy URL: `https://bot.example.com/privacy`.
   - User data deletion: `https://bot.example.com/data-deletion`.
   - App domains: `bot.example.com`.
   - احفظ بـ Save changes.
6. أعد تشغيل الخدمات بعد ملء `.env`:

   ```bash
   docker compose up -d
   ```

### 3.2 المنتجات والصلاحيات

1. في لوحة التطبيق أضف المنتجين **Messenger** و**Webhooks** (Add product ← Set up).
2. الصلاحيات الأربع التي يرفض الربط بدونها، والخامسة اختيارية:
   - `pages_messaging`
   - `pages_read_engagement`
   - `pages_manage_metadata`
   - `pages_show_list`
   - `pages_manage_engagement` (اختيارية، للرد العلني تحت التعليقات فقط). بدونها تُربط الصفحة، ويعمل الرد الخاص والبوت، ويتوقف الرد العلني، ويظهر سببه تحت الصفحة وفي «سجل التعليقات».

### 3.3 الـ webhook

في شاشة «صفحات فيسبوك» (القائمة: «فيسبوك» ← «الصفحات») يوجد قسم «Webhook تطبيق Meta». فيه «رابط الـ Callback» مع زر «نسخ»، وحالة «رمز التحقق (Verify token)»، و«حقول الـ webhook».

1. تحقق أولاً أن السيرفر يجيب. شغّل من أي جهاز، مع رمزك مكان `TOKEN`:

   ```bash
   curl "https://bot.example.com/api/facebook/webhook?hub.mode=subscribe&hub.verify_token=TOKEN&hub.challenge=12345"
   ```

   يجب أن يطبع `12345`.

2. في تطبيق Meta افتح Webhooks.
3. اختر من القائمة الكائن **Page**.
4. اضغط Subscribe to this object.
5. Callback URL: `https://bot.example.com/api/facebook/webhook`.
6. Verify token: نفس قيمة `FACEBOOK_WEBHOOK_VERIFY_TOKEN` حرفياً.
7. اضغط Verify and save.
8. في قائمة الحقول، اضغط Subscribe بجانب كل حقل من الأربعة:
   - `feed`: التعليقات.
   - `messages`: رسائل الزبائن.
   - `message_echoes`: ما ترسله الصفحة، ومنه ردود الفريق من Meta Business Suite.
   - `messaging_postbacks`: ضغطات زر «نحب هذا».

لا تحتاج أن تشترك الصفحة يدوياً: OpenReply يشترك فيها بهذه الحقول عند ربطها (القسم 4).

### 3.4 وضع Development ووضع Live

- **في وضع Development** لا يصل حدث ولا تُرسل رسالة إلا لمن له دور في التطبيق (App roles ← Roles: Administrator أو Developer أو Tester).
- للتجربة: أضف حساباً ثانياً كـ Tester، واقبل الدعوة منه، وعلّق وراسل منه.
- **لخدمة الزبائن الحقيقيين:**
  1. أكمل Business Verification لحساب Business.
  2. من App Review ← Permissions and Features، اطلب Advanced Access للصلاحيات الأربع، والخامسة إن كنت تستعمل الرد العلني.
  3. اشرح لكل صلاحية استعمالها، وسجّل فيديو قصيراً: تعليق ← رد خاص، رسالة ← رد البوت، رد من صندوق الرسائل.
  4. بعد الموافقة، حوّل App Mode إلى **Live** (أو Publish، حسب الواجهة).
- **اختياري:** ميزة Human Agent تسمح لإنسان بالرد حتى 7 أيام بدل 24 ساعة. اطلبها من App Review، ولا تفعّلها في OpenReply قبل الموافقة (القسم 9).

## 4. استخراج الـ token وربط الصفحات

يقبل OpenReply نوعين من الـ token:

- **user token** لمسؤول عن الصفحة: السيرفر يستبدله بـ token طويل المدة، ثم تختار الصفحات. **هذا الأسهل.**
- **Page token طويل المدة**: لصفحة واحدة.

يرفض السيرفر الـ token إن كان من تطبيق آخر، أو تنقصه صلاحية من الأربع المطلوبة، أو ينتهي خلال أقل من أسبوع.

### 4.1 الطريقة الأسهل: user token

1. افتح Graph API Explorer: developers.facebook.com/tools/explorer.
2. في Meta App اختر تطبيقك.
3. في User or Page اختر User Token.
4. في Permissions أضف الصلاحيات الأربع: `pages_messaging` و`pages_read_engagement` و`pages_manage_metadata` و`pages_show_list`، و`pages_manage_engagement` إن أردت الرد العلني تحت التعليقات.
5. اضغط Generate Access Token.
6. في نافذة فيسبوك اختر **كل الصفحات** التي تريد ربطها، ثم وافق.
7. انسخ الـ token من خانة Access Token.
8. في OpenReply اختر البراند الصحيح أولاً (القسم 5).
9. افتح «فيسبوك» ← «الصفحات».
10. في «ربط صفحة» الصق الـ token في خانة «الـ access token».
11. اضغط «ربط».
12. تظهر «اختر الصفحات التي تريد ربطها». علّم الصفحات.
13. اضغط «ربط الصفحات المختارة».

الـ token الذي يعطيه Explorer قصير (ساعة أو اثنتان)، لكن السيرفر يستبدله فوراً بـ token طويل المدة، ومنه يأخذ توكنات الصفحات.

> إن لم تظهر صفحة تديرها عبر Business portfolio، أضف `business_management` إلى الصلاحيات في الخطوة 4 وأعد التوليد.

### 4.2 طريقة Page token يدوياً

1. ولّد user token كما في الخطوات 1 إلى 7 أعلاه.
2. افتح Access Token Debugger: developers.facebook.com/tools/debug/accesstoken.
3. الصق الـ token واضغط Debug.
4. في الأسفل اضغط Extend Access Token، ثم انسخ الـ token الجديد (user token طويل المدة، نحو 60 يوماً).
5. ارجع إلى Graph API Explorer، والصق الـ token الطويل في خانة Access Token.
6. اكتب في خانة الطلب:

   ```text
   me/accounts?fields=name,access_token
   ```

7. اضغط Submit.
8. انسخ قيمة `access_token` الخاصة بصفحتك.
9. تحقق منه في Access Token Debugger: Type يجب أن يكون Page، وExpires يجب أن يكون Never.
10. الصقه في «ربط صفحة» واضغط «ربط».

### 4.3 لماذا لا ينتهي Page token

- الـ Page token المأخوذ من user token **طويل المدة** ليس له تاريخ انتهاء.
- يبقى صالحاً ما دام صاحبه مسؤولاً عن الصفحة، ولم يغيّر كلمة سر فيسبوك، ولم يحذف التطبيق أو صلاحياته.
- الـ Page token المأخوذ من user token **قصير** ينتهي معه بعد ساعة. السيرفر يرفضه برسالة «هذا الـ token ينتهي في …. استعمل Page token طويل المدة.»
- في قائمة «الصفحات المربوطة» يظهر في خانة «الـ token»: «لا ينتهي»، أو «ينتهي في …».
- العامل يفحص كل الصفحات يومياً. إن بطل token تصبح حالة الصفحة «الـ token غير صالح» (القسم 13).

### 4.4 بعد الربط

في «الصفحات المربوطة» لكل صفحة:

- الحالة: «نشطة» أو «الـ token غير صالح» أو «مفصولة».
- «حقول الـ webhook»: كل حقل بعلامة ✓ أو ✗.
- «الـ token» و«آخر webhook».
- خانة «البوت يرد في هذه الصفحة».
- أزرار «إعادة الاشتراك» و«فصل»، وزر «حذف» للصفحة المفصولة (للمالك فقط).

وفي قسم «Webhook تطبيق Meta» يظهر «عامل فيسبوك»: «يعمل»، أو رسالة بأنه لا يعمل.

**قواعد:**

- الربط والفصل للمالك والمسؤول فقط.
- صفحة واحدة لبراند واحد. إن كانت مربوطة ببراند آخر تظهر «هذه الصفحة مربوطة أصلاً ببراند آخر.»
- لنقل صفحة رُبطت بالبراند الخطأ: «فصل»، ثم «حذف» (المالك)، ثم اربطها من البراند الصحيح.
- «فصل» يحفظ الحملات والمحادثات. إعادة لصق token للصفحة نفسها تعيد تفعيلها.

### 4.5 صفحة رُبطت قبل إضافة الحقل `messaging_postbacks`

الصفحات المربوطة في نسخة سابقة اشتركت في ثلاثة حقول فقط، فلا تصلها ضغطات «نحب هذا».

1. افتح «فيسبوك» ← «الصفحات».
2. انظر «حقول الـ webhook» للصفحة. إن ظهر `✗ messaging_postbacks`:
3. تأكد أن الحقل مشترَك فيه في تطبيق Meta (القسم 3.3، الخطوة 8).
4. اضغط «إعادة الاشتراك» تحت الصفحة.
5. يجب أن تصبح الحقول الأربعة ✓.

إن بقي حقل ✗، يظهر تحت الصفحة سبب مثل: الحقل غير مضاف في webhook تطبيق Meta.

## 5. الوكالة: البراندات والفرق

### 5.1 إنشاء براند

1. افتح «الوكالة» ← «البراندات» (`/agency`).
2. في «إضافة براند» اكتب «اسم البراند».
3. اضغط «إنشاء».
4. تصبح مالك البراند، وينتقل إليه التطبيق.

كل براند مستقل: صفحاته، وحملاته، ومنتجاته، وقاعدة معرفته، وصندوق رسائله، وتنبيهاته، وبوت Telegram الخاص به.

لكل براند بطاقة فيها: «دورك»، و«صفحات فيسبوك»، و«حسابات إنستغرام»، و«الحملات النشطة»، و«الأعضاء»، و«تحتاج إنساناً» مقسّمة حسب التصنيف، و«آخر نشاط»، وزر «فتح» وزر «الفريق».

**من يستطيع الإنشاء:** من يملك مساحة عمل واحدة على الأقل. إن ضُبط `AGENCY_OWNER_EMAILS`، فهذه العناوين فقط. عضو فريق مدعوّ لا يستطيع.

**الحد:** يملك المستخدم الواحد 100 براند على الأكثر. بعدها تظهر «وصلت إلى الحد الأقصى لعدد البراندات.».

### 5.2 التبديل بين البراندات

- زر «فتح» في بطاقة البراند، أو
- القائمة المنسدلة أسفل الشريط الجانبي (تظهر حين تكون عضواً في براندين أو أكثر).

بعد التبديل تُحمَّل الصفحة من جديد، وكل الشاشات تعمل على البراند المختار. **تأكد من البراند قبل ربط صفحة أو تعديل منتجات.**

### 5.3 دعوة فريق البراند

1. في «البراندات»، اضغط «الفريق» في بطاقة البراند. يُفتح البراند على «الإعدادات».
2. انزل إلى قسم «الفريق».
3. اكتب بريد الشخص.
4. اختر الدور: «عضو» أو «مسؤول».
5. اضغط «دعوة».
6. تظهر الدعوة في «دعوات قيد الانتظار». اضغط «نسخ» لنسخ رابطها.
7. أرسل الرابط للشخص بنفسك (واتساب، بريد…). **التطبيق لا يرسل الدعوة بالبريد.**
8. يفتح الشخص الرابط، ويسجّل الدخول **بنفس البريد المدعوّ**.
9. الدعوة صالحة 14 يوماً. «إلغاء الصلاحية» يلغيها.

مع `ALLOWED_EMAILS` مضبوطاً، من له دعوة سارية أو عضوية يدخل دون إضافة بريده إلى `.env`.

### 5.4 الأدوار

| الدور | ما يستطيعه |
| --- | --- |
| **مالك** (OWNER) | كل شيء، ومنه حذف صفحة مفصولة. من ينشئ البراند يصبح مالكه |
| **مسؤول** (ADMIN) | ربط الصفحات وفصلها، والحملات، والمنتجات والاستيراد، وقاعدة المعرفة وشخصية البوت، والتنبيهات، ومراجعة الاقتراحات، والمقابلة الصوتية، ودعوة الأعضاء |
| **عضو** (MEMBER) | يرى كل شيء في البراند. في صندوق الرسائل يرد، ويتولّى المحادثات، ويرجعها للبوت. زر «أضِف إلى قاعدة المعرفة» يرسل منه اقتراحاً لمسؤول |

عضو الفريق لا يرى إلا البراند الذي دُعي إليه.

> الشاشة تعرض الأعضاء وأدوارهم، لكنها لا تتيح تغيير دور عضو موجود أو إزالته.

## 6. تعبئة قاعدة المعرفة والكتالوج

### 6.0 تشغيل البوت

**البوت متوقف افتراضياً في كل براند جديد.**

1. افتح «فيسبوك» ← «قاعدة المعرفة».
2. تبويب «الإعدادات».
3. علّم «البوت يرد على رسائل Messenger».
4. املأ «اسم النشاط».
5. «تعليمات للبوت (الأسلوب، اللهجة، العادات)»: اختياري.
6. «الرسالة التي تُرسل عند التحويل لإنسان»: الافتراضي «نرجعولك».
7. اضغط «حفظ التغييرات».
8. تحقق من خانة «الذكاء الاصطناعي»: يجب أن تقول «مضبوط (…)».
9. تحقق من «البوت في كل صفحة»: «يعمل» لكل صفحة. «إدارة الصفحات» يفتح شاشة الصفحات.

تبويبات «قاعدة المعرفة»: «الإعدادات»، «الشخصية ودليل البيع»، «المنتجات»، «التوصيل»، «الأسئلة المتكررة»، «القواعد»، «معلومات عامة»، «طرق التعبئة»، «جرّب البوت». بجانب تبويبات الإدخالات عددُ ما فيها.

### 6.1 الإدخالات النصية

في كل تبويب: املأ الحقول ثم «إضافة». «تعديل» و«حذف» تحت كل إدخال.

- **«التوصيل»:** «الولاية أو المنطقة»، «سعر التوصيل»، «مدة التوصيل وملاحظات».
- **«الأسئلة المتكررة»:** «السؤال» و«الجواب» بالضبط.
- **«القواعد»:** «القاعدة»، مثل «لا نقبل الاستبدال بعد 3 أيام»، و«تفاصيل (اختياري)».
- **«معلومات عامة»:** العنوان، أوقات العمل، طرق الدفع، رقم الهاتف.
- **«المنتجات»:** لم يعد يضيف منتجات. زر «فتح المنتجات» يفتح الكتالوج. المنتجات البسيطة القديمة لها زر «تحويل إلى بطاقة منتج».

اكتب الأسعار والأرقام كما يجب أن يقولها البوت حرفياً: البوت لا يقول رقماً غير مكتوب.

إن تجاوزت قاعدة المعرفة نحو 60 ألف حرف يظهر تحذير: الردود تصبح أبطأ وأغلى.

### 6.2 خصائص المنتجات

1. افتح «فيسبوك» ← «المنتجات» ← «خصائص المنتجات».
2. اضغط «إضافة خاصية».
3. «الاسم، كما يقوله زبائنك»: مثل السُّمك، المادة، مقاومة الماء، المقاس، القماش.
4. «النوع»: «نص» أو «رقم» أو «اختيار من قائمة» أو «نعم أو لا».
5. «الوحدة (اختياري)»: مثل mm أو m².
6. لـ «اختيار من قائمة»: «الخيارات، كل خيار في سطر» (خياران على الأقل).
7. اضغط «إضافة».
8. «نقل إلى الأعلى» و«نقل إلى الأسفل» لترتيبها.

كل بطاقة منتج في البراند تحمل هذه الخصائص، وتصبح أعمدة في نموذج الاستيراد.

### 6.3 بطاقة المنتج

1. «المنتجات» ← «منتج جديد».
2. **«الأساسيات»:** «اسم المنتج»، «الكود أو الرقم» (فريد داخل البراند)، «السعر، كما يجب أن يقوله البوت حرفياً»، «متوفر»، «رابط صفحة الهبوط»، «الوصف»، «طريقة التركيب أو الاستعمال».
3. **«الخصائص»:** قيم خصائص البراند.
4. **«الألوان أو الأنواع»:** اضغط «إضافة لون أو نوع» لكل لون:
   - «الكود» كما هو مكتوب على المنتج أو العيّنة، مثل `12-04`. البوت يتعرّف عليه في الرسائل والصور.
   - «الاسم (اختياري)»، «متوفر»، «السعر إن اختلف».
   - الصورة: «رفع صورة»، أو اختر من صور المنتج.
5. **«الصور»:** «إضافة صور»، JPEG أو PNG أو WebP، 5 MB على الأكثر. اختر «الصورة الرئيسية». اضغط الصور قبل رفعها، فهي تُحفظ في قاعدة البيانات وتكبّر النسخ الاحتياطية.
6. **«ساعد الزبون على الاختيار»** (معلومات صحيحة فقط):
   - «نقاط القوة، كل نقطة في سطر».
   - «المقارنة مع منتجات مشابهة أو مع المنافسين».
   - «لمن يصلح وأين (الاستعمالات، الغرف، الأماكن)».
   - «الأسئلة والتخوّفات المعروفة، مع أجوبتها»: «إضافة تخوّف وجوابه».
7. **«منتجات بديلة أو قريبة»**، مع «متى يُقترح (اختياري)».
8. **«الحالة»:** «نشط: يستعمله البوت»، أو «مسودة: في انتظار الاعتماد»، أو «في الأرشيف».
9. اضغط «إنشاء المنتج»، أو «حفظ التغييرات» عند التعديل.

البوت لا يقرأ إلا المنتجات النشطة. كلما كانت البطاقة أغنى أقنع البوت أكثر، دون أن يضيف معلومة من عنده.

في قائمة «المنتجات»: «ابحث بالاسم أو الكود»، والفلاتر «الكل» و«نشطة» و«المسودات» و«مؤرشفة»، و«المتوفرة فقط».

### 6.4 الاستيراد من جدول

1. «المنتجات» ← «استيراد من جدول بيانات».
2. **«حمّل النموذج»:** «تحميل Excel (.xlsx)» (فيه ورقة الألوان) أو «تحميل CSV» (المنتجات فقط). النموذج فيه خصائص البراند كأعمدة.
3. املأ الملف:
   - ورقة `Products`: منتج في كل سطر. الأعمدة التي عليها `*` إجبارية.
   - ورقة `Colours`: لون في كل سطر، مع كود المنتج.
   - ورقة `Read me` تشرح الصيغ بالعربية والفرنسية: نعم/لا، نقاط القوة في أسطر (Alt+Enter)، والتخوّفات بصيغة `السؤال => الجواب`.
   - **أعطِ كل منتج كوده:** به يُحدَّث المنتج لاحقاً. السطر بلا كود يُنشأ من جديد في كل استيراد.
4. جهّز الصور في **مجلد واحد**، واسم كل صورة هو الكود:
   - صورة المنتج: `WP-12.jpg`.
   - صورة اللون: `WP-12_12-04.jpg` أو `12-04.jpg`.
5. في «اختر ملفك وصورك»:
   - «ملف الجدول»: ملف .xlsx أو .csv، 5 MB على الأكثر.
   - «الصور (اختياري)»: «اختر مجلداً» أو «اختر صوراً».
6. اضغط «معاينة».
7. راجع المعاينة: «للإنشاء»، «للتحديث»، «مرفوض» مع السبب لكل سطر، و«صور مربوطة»، و«صور لا تطابق أي كود: لن تُحفظ».
8. صحّح الملف إن احتجت، ثم «معاينة» من جديد.
9. اضغط «استيراد N منتج».
10. انتظر «جارٍ رفع الصور» حتى تظهر «النتيجة».

ما تستورده كتبه إنسان، فيُعتمد مباشرة كمنتج نشط. التحديث لا يغيّر إلا أعمدة ملفك: الصور والألوان الأخرى والمنتجات المرتبطة تبقى. استيراد نفس الملف مرتين لا يغيّر شيئاً.

### 6.5 من منشورات الصفحة (مسودات)

1. «قاعدة المعرفة» ← «طرق التعبئة».
2. في «املأ قاعدة المعرفة من صفحتك» اختر «صفحة فيسبوك».
3. في «منتجات من آخر المنشورات» اضغط «اقرأ المنشورات».
4. «قيد التشغيل: قد يستغرق بضع دقائق. يمكنك مغادرة هذه الصفحة.»
5. تظهر النتيجة: «المنشورات المقروءة»، «المسودات المنشأة»… واضغط «راجع المسودات».
6. افتح كل مسودة. فيها «فتح المنشور» والجملة التي قُرئت منها.
7. قرّر:
   - عدّل البطاقة إن احتجت، واضغط «حفظ التغييرات» **قبل** الاعتماد.
   - «اعتماد»: يصبح المنتج نشطاً.
   - «دمج مع منتج موجود» ← اختر المنتج ← «دمج»: ينسخ ما ينقص ذلك المنتج فقط، ثم تُحذف المسودة.
   - «رفض» ← «نعم، ارفضها».

المنشور الذي قُرئ مرة لا يُقرأ ثانية. المسودات لا يستعملها البوت.

### 6.6 من المحادثات السابقة

1. «طرق التعبئة» ← «اقتراحات من المحادثات السابقة» ← «اقرأ المحادثات».
2. يقرأ كيف ردّت الصفحة على الزبائن، ويقترح أسعاراً ومقارنات وأجوبة تخوّفات. لا تُحفظ أسماء الزبائن ولا هواتفهم.
3. اضغط «راجع الاقتراحات».

Meta لا يعطي إلا جزءاً من تاريخ المحادثات.

### 6.7 المقابلة الصوتية عبر Telegram

تحتاج بوت Telegram محفوظاً في التنبيهات أولاً (القسم 10.1)، و`TELEGRAM_POLLING=true` (الافتراضي).

1. أرسل `/start` لبوت البراند من حسابك على Telegram.
2. «قاعدة المعرفة» ← «طرق التعبئة» ← «مقابلة صوتية عبر Telegram».
3. «المحادثة التي تجيب»: اختر محادثتك. إن لم تظهر، اضغط «جلب المحادثات الأخيرة».
4. «المنتجات»: «كل المنتجات النشطة، الأقل معلومات أولاً» أو «المنتجات التي أختارها فقط».
5. اضغط «بدء المقابلة».
6. يسألك البوت بالدارجة عن كل منتج: ما يميّزه، الفرق بينه وبين المشابه، ما يسأل عنه الزبائن، التخوّفات، لمن يصلح.
7. أجب **بفويس** أو بالكتابة. يفرّغ Gemini الفويس، ويحوّل الجواب إلى اقتراحات.

الأوامر في محادثة البوت:

| الأمر | ماذا يفعل |
| --- | --- |
| `/skip` | يتجاوز السؤال |
| `/next` | ينتقل للمنتج التالي |
| `/status` | أين وصلت المقابلة |
| `/stop` | يوقف المقابلة |
| `/interview` | يكمل مقابلة أُوقفت، خلال يوم من إيقافها |

- المقابلة تتوقف وحدها بعد **7 أيام** بلا جواب.
- ما أُجيب عنه يبقى في الاقتراحات.
- لبدء مقابلة جديدة: «بدء المقابلة» من الشاشة نفسها.

### 6.8 حلقة التعلّم

- بعد كل تحويل لإنسان، حين يرد الفريق (من صندوق الرسائل أو من Meta Business Suite)، يقترح النظام ما يصلح من الرد لقاعدة المعرفة أو للبطاقة.
- تحت كل رد لإنسان في صندوق الرسائل زر «أضِف إلى قاعدة المعرفة» (القسم 9.5).

### 6.9 شاشة المراجعة

1. فوق تبويبات «قاعدة المعرفة» تظهر شارة «N اقتراحات للمراجعة» حين يوجد ما يُراجَع. اضغطها.
2. شاشة «اقتراحات للمراجعة»: فلاتر «الكل»، «من منشور»، «من المحادثات»، «من مقابلة صوتية»، «من رد بعد التحويل لإنسان».
3. الاقتراحات مجمّعة حسب المنتج، أو تحت «قاعدة المعرفة».
4. لكل اقتراح: مصدره، و«النص الذي أُخذ منه»، و«فتح المحادثة» إن وُجدت.
5. عدّل النص إن احتجت.
6. «اعتماد» يكتبه في البطاقة أو في قاعدة المعرفة. «رفض» يحذفه.

المراجعة للمالك والمسؤول. **لا يُضاف شيء قبل الاعتماد.**

## 7. شخصية البوت وهدفه ودليل البيع

«قاعدة المعرفة» ← «الشخصية ودليل البيع». للمالك والمسؤول.

### 7.1 «من هو البوت»

- «الاسم الذي يقدّم به نفسه (اختياري)»: مثل «ليلى، من فريق Maison Lina».
- «اللهجة (فارغ: لهجة الزبون نفسه)»: مثل «الدارجة الجزائرية».
- «الأسلوب»: مثل «ودود، مختصر، يقول «خويا» و«ختي»».
- البوت لا يدّعي أبداً أنه إنسان.

### 7.2 «الهدف»

| الخيار | ماذا يفعل البوت |
| --- | --- |
| «البيع» | يساعد على الاختيار، ثم يأخذ معلومات الطلبية |
| «أخذ الطلبيات» | يجمع المعلومات بمجرد اهتمام الزبون |
| «جمع معلومات التواصل» | يجمع المعلومات ليتصل الفريق |
| «الإجابة فقط» | يجيب فقط؛ الزبون الجاهز للشراء يُحوَّل لإنسان |

و«ملاحظات حول الهدف (اختياري)».

### 7.3 «معلومات الطلبية التي يجمعها البوت»

علّم ما يلزم: «الولاية»، «اللون أو النوع»، «الكمية»، «الاسم»، «رقم الهاتف»، «العنوان». الافتراضي الخمسة الأولى.

- الكود يتحقق من كل قيمة: ولاية من الـ58، رقم هاتف صحيح، لون من ألوان المنتج نفسه.
- حين تكتمل كلها، يرسل البوت رده، ثم يحوّل المحادثة بتصنيف **«طلبية جاهزة للتأكيد»**. يصل التنبيه مع ملخص الطلبية.
- «إرجاع للبوت» يمسح الطلبية.

### 7.4 «دليل البيع»

- نص قواعد خطوة بخطوة. الافتراضي مبني على التعاطف التكتيكي (Chris Voss)، وNEPQ، وJobs To Be Done، وHEARD للغاضب، وCialdini بمعلومات صحيحة فقط.
- عدّله كما تريد، أو اضغط «استرجاع الدليل الافتراضي».
- تحت النص: «الدليل الافتراضي» أو «دليل هذا البراند». الدليل الافتراضي غير المعدَّل يستفيد من تحسينات النسخ القادمة.
- اضغط «حفظ التغييرات».

### 7.5 حالة الزبون

مع كل رد يصنّف البوت الزبون، وتظهر شارة في صندوق الرسائل وفي «جرّب البوت»: «يسأل عن السعر فقط»، «متردد»، «جاهز للشراء»، «غاضب»، «جملة»، «طلبية خاصة». المحايد بلا شارة.

### 7.6 الحارس

القواعد الصارمة فوق الدليل دائماً. الحارس يرفض الرد إن كان فيه، دون أن يكون مكتوباً عند البراند:

- سعر أو رقم أو مبلغ أو رابط.
- تخفيض، أو توصيل مجاني، أو هدية.
- ندرة أو استعجال («آخر قطعة»)، أو «الأحسن في السوق»، أو ضمان أو استرجاع للمال.

عند الرفض، يُطلب من البوت إعادة الصياغة **مرة واحدة**. إن تكرر، يرسل «نرجعولك» ويحوّل المحادثة لإنسان. ما يكتبه الزبون («c'est 2000 DA ؟») لا يعطي البوت سعراً يؤكده.

### 7.7 «جرّب البوت»

1. «قاعدة المعرفة» ← «جرّب البوت».
2. اكتب في «رسالة الزبون» سؤالاً كما يكتبه الزبون، واضغط «إرسال».
3. ترى: رد البوت، و«الزبون: …»، أو «سيحوّل المحادثة لإنسان» مع التصنيف و«السبب: …» و«سيصل الزبون: …».
4. وترى «الطلبية حتى الآن:»، والصور أو المقارنة التي كان سيرسلها.
5. تابع المحادثة برسائل أخرى. «البدء من جديد» يمسحها.

لا يُرسل أي شيء على Messenger ولا يخرج أي تنبيه. يستعمل الإعدادات **المحفوظة**: احفظ قبل التجربة.

**الحد:** 60 تجربة في الساعة لكل براند، لأن كل تجربة طلب لـ Gemini. بعدها تظهر «تجارب البوت كثيرة في هذه الساعة. حاول لاحقاً.».

## 8. حملات التعليقات

1. «فيسبوك» ← «الحملات» ← «حملة جديدة».
2. «اسم الحملة».
3. «صفحة فيسبوك».
4. المنشور:
   - «الرد على التعليقات في كل المنشورات» (يشمل الإعلانات)، أو
   - اختر «المنشور» من القائمة، أو الصق «معرّف المنشور».
5. «الكلمات المفتاحية»: اكتب كلمة واضغط Enter أو الفاصلة. أو علّم «الرد على كل التعليقات».
   - «كلمات كاملة فقط»: الصيغ العربية تطابق دائماً («سعر» تطابق «السعر» و«بالسعر» و«سعرو»).
   - تطابق أيضاً «prix» و«PRIX» و«price?».
6. **«الرد الخاص»:**
   - الرسالة: `{name}` يُستبدل بالاسم الأول للشخص.
   - «نص الزر (20 حرفاً كحد أقصى)».
   - «رابط صفحة الهبوط»، يبدأ بـ `https://`.
   - «إضافة معاملات UTM إلى الرابط».
7. **الرد العلني (اختياري):** علّم «الرد علنياً أيضاً تحت التعليق»، واكتب رداً في كل سطر. يُختار واحد عشوائياً.
8. «عن ماذا تتحدث هذه الحملة؟ (للبوت)»: حين يرد الشخص على الرد الخاص، يعرف البوت ما جاء من أجله.
9. «المنتج (اختياري)»: يقرأ البوت بطاقته الكاملة في محادثات هذه الحملة.
10. راجع «معاينة»، وتأكد من «الحملة نشطة»، واضغط «إنشاء الحملة».

**القواعد:**

- رد خاص **واحد** لكل تعليق، وخلال **7 أيام** من التعليق.
- حملة واحدة تتولى التعليق: حملة المنشور المحدد أولاً، ثم «كل المنشورات».
- تعليقات الصفحة نفسها تُتجاهل.
- **الرد الخاص لا يفتح نافذة 24 ساعة.** تُفتح حين يرد الشخص، وعندها يأخذ البوت دوره.
- «إيقاف» و«استئناف» و«تعديل» و«حذف» في قائمة الحملات.
- تبويب «سجل التعليقات»: كل تعليق مطابق وحالته («أُرسلت»، «فشلت»، «غير مؤكَّدة»، «أقدم من 7 أيام»، «لا يمكنه استقبال الرسائل»…) مع فلتر «كل الحالات».
- «غير مؤكَّدة»: فيسبوك لم يؤكد الإرسال، ولا يعيده النظام وحده حتى لا يتكرر.

## 9. صندوق رسائل Messenger

«فيسبوك» ← «صندوق الرسائل» (`/facebook/inbox`). يتحدّث كل 10 ثوانٍ.

### 9.1 القائمة

- الفلاتر: «الكل»، «تحتاج إنساناً» (مع العدد)، «مع البوت»، «مع إنسان».
- «كل التصنيفات»: فلتر بسبب التحويل، و«كل الصفحات».
- شارة ملوّنة للتصنيف، وشارة حالة الزبون.

### 9.2 من يجيب

| الحالة | المعنى |
| --- | --- |
| «البوت» | البوت يجيب على الرسالة التالية |
| «إنسان» | البوت صامت في هذه المحادثة |

تنتقل المحادثة إلى إنسان حين:

- يحوّلها البوت («حُوّلت لإنسان: …»)، ويرسل «نرجعولك» مرة واحدة.
- يضغط أحد الفريق «تولّي المحادثة».
- يرسل أحد الفريق رداً من الصندوق: «إرسال رد يأخذ المحادثة من البوت.» تنتقل المحادثة لحظة الضغط على «إرسال»، حتى لو فشل الإرسال، فلا يرد البوت فوق الرد.
- يرد أحد من Meta Business Suite أو تطبيق Pages: «ردّ إنسان من Meta Business Suite»، والرسالة بعلامة «من Meta».

### 9.3 الإرجاع للبوت

1. افتح المحادثة.
2. اضغط «إرجاع للبوت».
3. أكّد: «إرجاع المحادثة للبوت؟ سيرد على الرسالة التالية.»

الإرجاع يمسح التصنيف والطلبية المجمّعة.

### 9.4 نافذة 24 ساعة

- Messenger لا يسمح بالرد إلا خلال 24 ساعة من آخر رسالة كتبها الزبون.
- في رأس المحادثة: «باقي N سا وM د للرد»، أو «نافذة الرد مغلقة».
- بعد انتهائها يرفض الصندوق الإرسال برسالة واضحة. لا حل إلا أن يكتب الزبون من جديد.
- **اختياري:** وسم HUMAN_AGENT يمدّها إلى 7 أيام للإنسان فقط (البوت يبقى على 24 ساعة). بعد موافقة Meta على Human Agent:
  1. في `.env` اكتب `FACEBOOK_HUMAN_AGENT_TAG=true`.
  2. طبّق التغيير:

     ```bash
     docker compose up -d
     ```

  3. يظهر «باقي N أيام للرد (وسم HUMAN_AGENT)».

### 9.5 إضافة رد إنسان إلى قاعدة المعرفة

1. تحت رد أرسله إنسان، اضغط «أضِف إلى قاعدة المعرفة».
2. عدّل «السؤال» و«الجواب».
3. اضغط «حفظ».
4. المالك والمسؤول: «تمت الإضافة إلى قاعدة المعرفة.» العضو: «أُرسل إلى مسؤول للمراجعة.»

### 9.6 ما يظهر في المحادثة

- **رسالة صوتية:** شارة «رسالة صوتية» مع النص المفرّغ، أو «جارٍ التفريغ…»، أو «تعذّر تفريغها» مع السبب.
- **صورة:** «جارٍ قراءة الصورة…»، أو «تعرّف البوت على: …»، أو «قد يكون: …»، أو «لم يتعرّف عليه البوت».
- **«معلومات الطلبية التي جمعها البوت»**.
- **خط زمني:** «حُوّلت لإنسان»، «تولّاها …»، «أرجعها … للبوت».
- **«من الحملة …»** إن جاء الزبون من تعليق.

رابط التنبيه يفتح المحادثة مباشرة، ويبدّل البراند إن كنت عضواً فيه.

## 10. تنبيهات التحويل لإنسان على Telegram والبريد

«فيسبوك» ← «التنبيهات» (`/facebook/alerts`). التعديل للمالك والمسؤول.

يصل تنبيه عند **كل** تحويل لإنسان: البراند، والصفحة، والزبون، والتصنيف، والسبب، وآخر رسالة (أو النص المفرّغ)، وزر «فتح المحادثة». الطلبية الجاهزة تصل بعنوان «🛒 طلبية جاهزة للتأكيد» مع ملخصها. لا تنبيه عند التولّي اليدوي ولا عند رد من Meta Business Suite.

### 10.1 إنشاء بوت Telegram

ننصح ببوت مستقل لكل براند، لا يستعمله أي برنامج آخر.

1. في Telegram افتح محادثة مع **@BotFather**.
2. أرسل:

   ```text
   /newbot
   ```

3. اكتب اسم البوت، مثل `Maison Lina Alerts`.
4. اكتب اسم مستخدم ينتهي بـ `bot`، مثل `maisonlina_alerts_bot`.
5. يعطيك BotFather الـ token، بصيغة `123456789:AA…`. انسخه.
6. في OpenReply: قسم «بوت Telegram»، الصقه في «توكن البوت».
7. اضغط «حفظ».
8. يظهر «مربوط: @اسم_البوت».

### 10.2 الحصول على الـ Chat ID

**لشخص:**

1. كل شخص يفتح البوت في Telegram ويرسل `/start`.
2. في «إضافة مستلم» اختر «القناة»: «Telegram».
3. اضغط «جلب المحادثات الأخيرة».
4. اضغط «اختيار» بجانب المحادثة. يُملأ «معرّف المحادثة (Chat ID)».

**لمجموعة:**

1. أضف البوت إلى المجموعة.
2. أرسل فيها `/start@اسم_البوت` (مثل `/start@maisonlina_alerts_bot`).
3. «جلب المحادثات الأخيرة» ← «اختيار».
4. معرّف المجموعة **سالب**، ويبدأ غالباً بـ `-100`.

كل محادثة في القائمة تظهر باسمها، وتحته نوعها («محادثة خاصة» أو «مجموعة» أو «قناة Telegram») و@username إن وُجد والمعرّف. الاسم يختاره صاحب المحادثة بنفسه، فتأكد من النوع والمعرّف قبل «اختيار».

> **Privacy mode:** البوت في مجموعة لا يرى الرسائل العادية، بل الأوامر الموجهة إليه فقط. هذا لا يؤثر على إرسال التنبيهات، بل على «جلب المحادثات» فقط. لذلك أرسل الأمر بصيغة `/start@اسم_البوت`. أو عطّل Privacy mode من @BotFather بالأمر `/setprivacy`.

**يدوياً**، إن لم تظهر المحادثة: افتح في المتصفح (مع توكنك مكان `<TOKEN>`):

```text
https://api.telegram.org/bot<TOKEN>/getUpdates
```

وابحث عن `"chat":{"id":…}`. Telegram يحتفظ بالرسائل الجديدة 24 ساعة فقط: إن كانت القائمة فارغة، أرسل رسالة جديدة للبوت.

### 10.3 المستلمون

1. «إضافة مستلم».
2. «القناة»: «Telegram» أو «البريد الإلكتروني».
3. «الاسم»: مثل «سارة، المبيعات».
4. «معرّف المحادثة (Chat ID)» أو «عنوان البريد».
5. علّم «افتراضي (يستقبل التصنيفات التي لم يُحدَّد لها أحد)» لمستلم واحد على الأقل.
6. اضغط «إضافة».

لكل مستلم: «إرسال تجريبي»، «جعله افتراضياً» أو «إلغاء الافتراضي»، «تعطيل» أو «تفعيل»، «حذف».

**البريد** يحتاج `RESEND_API_KEY` (أو `EMAIL_SERVER`) و`EMAIL_FROM` في السيرفر. يظهر «تُرسل التنبيهات بالبريد من …». لمرسل مختلف: `ALERTS_EMAIL_FROM`.

### 10.4 التوجيه حسب التصنيف

قسم «التوجيه»: جدول، صف لكل تصنيف وعمود لكل مستلم.

1. علّم من يستقبل كل تصنيف. مثلاً:
   - «طلبية جاهزة للتأكيد» و«طلبية جملة» ← المبيعات.
   - «شكوى» ← صاحب البراند.
   - «رسالة صوتية تعذّر تفريغها» و«سؤال غير موجود في قاعدة المعرفة» ← خدمة الزبائن.
2. اضغط «حفظ التوجيه».

التصنيفات السبعة: «طلبية جاهزة للتأكيد»، «طلبية جملة»، «طلبية خاصة»، «شكوى»، «سؤال غير موجود في قاعدة المعرفة»، «رسالة صوتية تعذّر تفريغها»، «أخرى».

تصنيف بلا أحد يذهب للمستلمين الافتراضيين. إن لم يوجد افتراضي يظهر تحذير، ولا يُرسل تنبيه. المحادثة تبقى في صندوق الرسائل في كل الأحوال.

### 10.5 الاختبار

1. اضغط «إرسال تنبيه تجريبي لكل المستلمين المفعّلين».
2. لكل مستلم: «…: أُرسل التنبيه التجريبي.»، أو سبب الفشل.
3. تحقق من وصول «🧪 تنبيه تجريبي من OpenReply».
4. «آخر التنبيهات» يعرض ما أُرسل وأخطاءه.

**الحد:** 10 تجارب في الساعة لكل براند، والضغطة الواحدة تجربة واحدة مهما كان عدد المستلمين. بعدها تظهر «تنبيهات التجربة كثيرة في هذه الساعة. حاول لاحقاً.».

## 11. إيقاف الردود الآلية لـ Meta Business Suite

**لماذا:** كل رسالة ترسلها الصفحة من خارج OpenReply يعتبرها النظام رداً من إنسان، فيُسكت البوت في تلك المحادثة. الرد الفوري ورسالة الغياب من Meta تُرسل قبل البوت، فتأخذ منه المحادثة كل مرة.

لكل صفحة يعمل فيها البوت:

1. افتح business.facebook.com واختر الصفحة.
2. Inbox ← Automations.
3. أوقف:
   - Instant reply.
   - Away message.
   - Frequently asked questions.
   - أي رد آلي على التعليقات أو الرسائل.
4. لا تشغّل بوتاً آخر أو تطبيق أتمتة آخر (ManyChat وغيره) على نفس الصفحة: سيُعامَل كإنسان ويصمت البوت.
5. في إعدادات الصفحة (Advanced messaging)، تأكد أن لا تطبيق آخر يجيب على الرسائل.

ردود فريقك من Meta Business Suite مسموحة: تسجَّل «من Meta»، وتأخذ المحادثة من البوت، حتى «إرجاع للبوت».

## 13. استكشاف الأخطاء

**أوامر مفيدة** (من `deploy/vps`):

```bash
docker compose ps
```

```bash
docker compose logs --since 30m app
```

```bash
docker compose logs --since 30m facebook-worker
```

### Meta لا يتحقق من الـ webhook

- جرّب أمر `curl` في القسم 3.3. يجب أن يطبع الرقم.
- **403:** الرمز في Meta لا يطابق `FACEBOOK_WEBHOOK_VERIFY_TOKEN`، أو المتغير فارغ. صحّحه، ثم `docker compose up -d`.
- **لا جواب أو خطأ شهادة:** سجل DNS لا يشير للـ VPS، أو المنفذ 443 مغلق. راجع سجلات Caddy:

  ```bash
  docker compose logs --since 1h caddy
  ```

- الرابط يجب أن يكون `https://…/api/facebook/webhook` بالضبط.

### الأحداث لا تصل

- «آخر webhook»: «لم يصل شيء بعد».
- التطبيق في Development، والمعلّق أو المرسل بلا دور في التطبيق.
- حقل ✗ في «حقول الـ webhook»: أضفه في Meta، ثم «إعادة الاشتراك».
- الحقول الأربعة غير مشترَك فيها في Webhooks ← Page في تطبيق Meta.
- الـ token من تطبيق آخر: الـ webhooks تصل فقط للتطبيق الذي أصدر الـ token.
- في سجلات `app` تظهر `Invalid signature`: قيمة `FACEBOOK_APP_SECRET` خاطئة.
- «عامل فيسبوك» لا يعمل: راجع `docker compose ps` وسجلات `facebook-worker`.

### الـ token انتهى

- الحالة «الـ token غير صالح»، أو صندوق الرسائل يقول «هذه الصفحة لا تستطيع إرسال الرسائل: أعد ربطها من صفحات فيسبوك.»
- السبب عادة: تغيير كلمة سر فيسبوك، أو حذف دور المسؤول، أو إزالة التطبيق.
- الحل: ولّد token جديداً (القسم 4) والصقه في «ربط صفحة». الصفحة نفسها تُحدَّث، وتبقى حملاتها ومحادثاتها.

### البوت لا يرد

راجع بالترتيب:

1. **البوت متوقف:** «قاعدة المعرفة» ← «الإعدادات» ← «البوت يرد على رسائل Messenger»، و«البوت يرد في هذه الصفحة» في شاشة الصفحات.
2. **مفتاح الذكاء الاصطناعي:** «غير مضبوط: اضبط GOOGLE_API_KEY في السيرفر.» بدونه كل رسالة تُحوَّل لإنسان بـ «نرجعولك». مفتاح خاطئ أو حصة منتهية تعطي تحويلاً بسبب «خدمة الذكاء الاصطناعي لم تجب.»
3. **المحادثة مع إنسان:** «مع إنسان». اضغط «إرجاع للبوت».
4. **رد آلي من Meta** أخذ المحادثة: القسم 11.
5. **النافذة مغلقة:** «نافذة الرد مغلقة». البوت لا يرسل بعد 24 ساعة.
6. **السقف:** أكثر من 20 رداً آلياً في ساعة في نفس المحادثة.
7. **ملصق أو إعجاب فقط:** لا يرد عليه البوت.
8. **الصفحة** ليست «نشطة»، أو العامل متوقف.

### Telegram: «لهذا البوت webhook عند خدمة أخرى…» (409)

- البوت مستعمل في خدمة أخرى لها webhook، أو برنامج آخر يقرأ نفس البوت. Telegram يرفض القراءة من مكانين (خطأ 409).
- التنبيهات تُرسل رغم ذلك، لكن «جلب المحادثات» والمقابلة الصوتية لا يعملان.
- **الحل الأنظف:** بوت جديد من @BotFather خاص بـ OpenReply.
- **أو** احذف الـ webhook القديم، إن لم تعد تحتاج الخدمة الأخرى:

  ```text
  https://api.telegram.org/bot<TOKEN>/deleteWebhook
  ```

- **أو** أدخل الـ Chat ID يدوياً في «إضافة مستلم».

### Telegram: التنبيه التجريبي فشل

- «Telegram لا يجد هذه المحادثة…»: الشخص لم يرسل `/start` للبوت، أو البوت ليس في المجموعة.
- «البوت لا يستطيع الكتابة هناك…»: حُظر البوت أو أُزيل من المجموعة.
- «توكن بوت Telegram لم يعد صالحاً…»: ولّد token من @BotFather واحفظه من جديد.

### الصوت لا يُفرَّغ

- تحت الرسالة: «تعذّر تفريغها» مع السبب، والمحادثة محوّلة بتصنيف «رسالة صوتية تعذّر تفريغها».
- **ffmpeg:** موجود في صورة `facebook-worker`، و`FFMPEG_PATH=ffmpeg`. إن شغّلت العامل خارج Docker، ثبّت ffmpeg واضبط المسار.
- `GOOGLE_API_KEY` غير مضبوط أو لا يعمل.
- الرسالة أكبر من `FACEBOOK_AUDIO_MAX_BYTES` (15 MB افتراضياً).
- العامل كان متوقفاً: روابط Messenger مؤقتة، فيضيع الملف.
- أكثر من 20 رسالة صوتية أو صورة في ساعة من المحادثة نفسها: تُحفظ ولا تُقرأ، وتحتها «رسائل صوتية أو صور كثيرة في ساعة واحدة: لم تُقرأ هذه.»، وتُحوَّل المحادثة لإنسان.
- راجع سجلات `facebook-worker`.

### الصور لا يُتعرَّف عليها

- «تعذّرت قراءة الصورة»: لا مفتاح AI، أو رابط منتهٍ، أو صورة أكبر من `CUSTOMER_IMAGE_MAX_BYTES` (8 MB).
- «رسائل صوتية أو صور كثيرة في ساعة واحدة: لم تُقرأ هذه.»: الحد 20 رسالة صوتية أو صورة في الساعة لكل محادثة.
- «لم يتعرّف عليه البوت»:
  - الكود على الصورة غير مكتوب في البطاقة. أضف كود المنتج وأكواد الألوان كما هي على العيّنة.
  - صورة بلا كود: المقارنة تكون مع صور المنتجات، فأضف صوراً واضحة لكل منتج.
  - المنتج مسودة أو مؤرشف.
- «قد يكون: … / …»: كودان متشابهان (12 و17). البوت يسأل الزبون، وهذا مقصود.
- البوت لا **يرسل** الصور: يحتاج عنواناً https عاماً (الدومين المنشور، لا localhost)، وصوراً على الألوان أو المنتجات.

### الإعدادات لا تتغير بعد تعديل `.env`

`docker compose restart` لا يعيد قراءة `.env`. استعمل:

```bash
docker compose up -d
```

## 14. التحديث والسجلات والنسخ الاحتياطي

كل الأوامر من المجلد:

cd /opt/openreply/deploy/vps

1. خذ نسخة احتياطية (14.3).
2. اسحب التحديث:

   ```bash

   ```

3. أعد البناء والتشغيل:

   ```bash
   docker compose up -d --build
   ```

4. الـ migrations تُطبَّق وحدها عند إقلاع التطبيق.
5. تحقق:

   ```bash
   docker compose ps
   ```

### 14.2 السجلات والحالة

```bash
docker compose ps
```

```bash
docker compose logs -f app
```

```bash
docker compose logs -f worker facebook-worker
```

```bash
docker compose logs --since 1h caddy
```

`Ctrl+C` يخرج من المتابعة دون إيقاف شيء.

حالة عامل فيسبوك تظهر في «صفحات فيسبوك». للتشخيص افتح `https://bot.example.com/api/facebook/health` وأنت مسجّل الدخول. آخر أخطاء العامل واسم السيرفر يظهران لمشغّل التنصيب فقط: عناوين `AGENCY_OWNER_EMAILS`، أو مالك البراند إن لم يُضبط.

### 14.3 النسخ الاحتياطي

`backup.sh` يأخذ نسخة من Postgres إلى `./backups`، ويحتفظ بأحدث 14 نسخة.

1. جرّبه يدوياً:

   ```bash
   ./backup.sh
   ```

2. جدوله يومياً، افتح الـ crontab:

   ```bash
   crontab -e
   ```

3. أضف هذا السطر (كل يوم 03:15):

   ```text
   15 3 * * * /opt/openreply/deploy/vps/backup.sh >> /var/log/openreply-backup.log 2>&1
   ```

4. **انسخ النسخ خارج السيرفر.** في `.env` اضبط `BACKUP_UPLOAD_CMD`، مثلاً مع rclone:

   ```text
   BACKUP_UPLOAD_CMD=rclone copyto "$1" remote:openreply/$(basename "$1")
   ```

5. إعدادات أخرى في `.env`: `BACKUP_DIR` (المجلد)، و`BACKUP_KEEP` (عدد النسخ).

**احفظ أيضاً ملف `.env`**، وخاصة `ENCRYPTION_KEY`، في مكان آمن خارج السيرفر. النسخة بدونه لا تعيد توكنات الصفحات وTelegram.

Redis فيه الطوابير فقط، ولا يدخل في النسخة.

### 14.4 الاستعادة

**هذا يستبدل البيانات الحالية.**

1. أوقف التطبيق والعمّال:

   ```bash
   docker compose stop app worker facebook-worker cron
   ```

2. استعد النسخة (ضع اسم ملفك):

   ```bash
   docker compose exec -T postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner' < backups/openreply-YYYYMMDDTHHMMSSZ.dump
   ```

3. شغّلها من جديد:

   ```bash
   docker compose start app worker facebook-worker cron
   ```

**على سيرفر جديد:** نصّب كما في القسم 2 بنفس `.env` (نفس `ENCRYPTION_KEY` و`POSTGRES_PASSWORD`)، وشغّل `docker compose up -d --build`، ثم استعد النسخة بالخطوات أعلاه. بعد تغيير IP السيرفر، حدّث سجل DNS.
